# LunarShroud 1.0 视觉改版 · 设计简报

> 本文件是本轮视觉改版的决策记录。改样式前先读这里；改完对照 §5 自检。
>
> **⚠️ 2026-11-03 修订：窗口结构已从三栏改回两栏。** 下文 §2/§3 描述的
> "图标轨道 + 列表列 + 内容区 + 右侧检查器"是**第一版**；实测发现三栏会让
> 窗口被切成四条互相独立的带子，而且列表列的显隐开关藏在右上角第三个位置、
> 关掉之后没人找得回来。现在的结构是：
>
> ```
> .app-header     品牌 / 居中模型胶囊（含停止按钮）/ 状态 / 语言·主题·关于
> .app-body
> ├── .sidebar   单列：导航项 → 当前页列表 → 底部动作（宽度 200–420，可拖）
> └── .main-content
> .app-statusbar  CPU / 内存 / 显存 + 后端状态
> ```
>
> 三层表面的令牌（canvas / panel / surface）与 §4 的颜色、字体、形状、
> 动效决策**全部保留**，只有列的划分变了。具体清单见
> `CHANGELOG.md` 的 `[Unreleased] - 2026-11-03`。

## 1. 简报（Brief）

- **主体**：Windows 桌面端本地 LLM 运行时。用户自带 llama.cpp 构建（CPU / Vulkan /
  OpenVINO / ROCm 可插拔），模型是普通 `.gguf` 文件，全部数据留本机、离线可用、
  无云端账号、无遥测。
- **受众**：已经理解"模型就是文件 + 后端就是进程"的人。他们每天开它、聊很久、
  同时挂几个实例、边聊边看显存。不是第一次接触 AI 的好奇用户。
- **主屏的任务**：Chat。用户来这里是为了**读模型写出的长文**并把对话攒成资产；
  仪表盘/日志/知识库是"支撑面"，出现频率低于 Chat 一到两个数量级。
- **密度**：偏紧。桌面工具，14px 正文、12px 元信息、8–40px 间距刻度。
- **语言**：中文为默认，英文等价；两套键必须奇偶一致（已由 `i18n.test.mjs` 守护）。

### 三个拒绝项（本设计不得像的东西）

1. **不像"AI SaaS 落地页"**：不要渐变文字标题、不要漂浮的装饰性发光、不要把每块
   内容塞进同一种圆角卡片再配同一种柔光阴影。
2. **不像当前版本**：现状的三个具体病灶——(a) 用户消息是亮紫气泡、助手消息却是
   裸文字，两者不在同一视觉语言里；(b) composer 是一个高 200px 的空白盒，把
   视线从对话上拽走；(c) 三栏（图标轨道 + 会话列表 + 主区）各用自己的底色和
   边框，界面被切成三条互不相关的带子。
3. **不像 generic bootstrap**：不要 `#4F46E5` 靛蓝主色、不要 `0 4px 6px rgba(0,0,0,.1)`
   这一档阴影、不要左上角 8px 圆角配左上角 0 的"聊天气泡"。

## 2. 业务参考（用户指定）

- **LM Studio 0.4.x**：三段式窗口（左侧图标+列表 / 中间对话 / 右侧检查器）、
  顶栏中央是"当前模型"胶囊、底部状态条常驻显存与内存读数、composer 是一个
  带 + / 工具 / Think / Vision 的紧凑输入条。
- **Vercel AI Chatbot**：对话流以"助手可读长文"为中心，用户气泡短、右对齐、
  低对比；空态用少量建议卡片而不是一大块插画。
- **assistant-ui**：composer 与消息流共享同一条内容列宽；工具调用与思考过程
  是可折叠的 inline 组件，不是弹窗。
- **shadcn/ui**：`--radius` 单值、边框极淡、hover 只改底色不改尺寸。

## 3. 方向（Direction）

**"macOS 原生工具"** —— 把窗口当成一个原生 App，而不是一个网页套了个壳。

选它的理由：用户点名要 macOS 系统软件的风味；而这个产品的性质（本机进程、本机
文件、无账户）恰好就是 macOS 桌面工具的性质。LM Studio 本身就是这套语言在
Windows 上的移植（蓝紫强调色 + 灰阶分层 + 紧凑顶栏）。

为什么不是"玻璃拟态"：模糊层叠在长文本阅读区会降低对比度并拖慢 WebView2 的
合成；本产品的主屏是**读长文**，模糊只在浮层和 4 处背景图路径上保留。
为什么不是"极简瑞士风"：瑞士风适合营销页；这是个有 9 个页面、60+ 参数的
工具，需要层级和边框表达结构。

### 唯一一个大胆的元素（signature）

**顶栏中央的"当前模型胶囊"**：整窗唯一使用强调色的实心元素，显示模型名 + 一个
在线状态点，点击打开模型切换器。全屏的强调色预算都给它。其余地方强调色只用于
焦点环、激活项的左缘指示条和少数链接。

## 4. 令牌方案（Token plan）

### 颜色

| 角色 | 浅色 | 深色 | 依据 |
|---|---|---|---|
| 画布 `--color-bg` | `#F5F5F7` | `#161618` | macOS windowBackgroundColor |
| 面板 `--color-bg-elevated` | `#FFFFFF` | `#1D1D20` | 侧栏/顶栏/卡片浮起一层 |
| 文字 `--color-text` | `#1D1D1F` | `#F2F2F5` | labelColor，16.8:1 |
| 次文字 `--color-text-secondary` | `#4A4A50` | `#B4B4BE` | secondaryLabel |
| 三级文字 `--color-text-tertiary` | `#6E6E73` | `#8E8E96` | tertiaryLabel，4.66:1 过 AA |
| 描边 `--color-border` | `#E3E3E8` | `#2E2E34` | separatorColor（更细更淡） |
| 强调 `--color-primary-fill` | `#5B5BD6` | `#6E6EE8` | systemIndigo 系，白字 5.37:1 |

**刻意保留但改造的**：危险/成功/警告三色沿用现有语义色（用户已有肌肉记忆，
且徽标文案不依赖颜色单独表意）。

### 字体

- 界面：`-apple-system, "Segoe UI Variable Text", "Segoe UI", "PingFang SC",
  "Microsoft YaHei UI", sans-serif` —— 先 Apple 栈再 Windows 栈，CJK 用系统中文
  界面字体（不是正文的宋体/雅黑旧版）。
- 等宽：`"SF Mono", "Cascadia Mono", "JetBrains Mono", Consolas, monospace` ——
  路径、命令、token 计数、日志。
- 字号阶梯收敛为：11 / 12 / 13 / 14 / 16 / 20 / 24（现有 8 档太多的近邻档合并）。
  正文 **14px**（桌面下限），长文阅读 14px/1.7。

### 形状与层级

- 圆角单值族：`4 / 6 / 8 / 12 / 18`。卡片 12，控件 8，胶囊 999。
- 阴影只留 3 档，且**都带色相**（用 `oklch` 把黑调到靛蓝方向），不用纯黑 rgba。
- 边框统一 1px + 更淡的颜色；不再用"边框 + 阴影"双重勾边。

### 动效

- `120ms` 用于 hover/焦点，`180ms` 用于展开/收起，`280ms` 只给浮层进入。
- 只动 `background-color / color / opacity / transform`。尊重
  `prefers-reduced-motion`（已有令牌机制）。

## 5. 自检清单（改完逐条确认）

- [ ] 每个文字/UI 配对都过 WCAG（用 `wcag.py` 复核，不靠肉眼）
- [ ] 键盘焦点环在浅色与深色背景上都可见，且与 hover 不同
- [ ] 颜色不单独承载语义（状态点同时有文字）
- [ ] 中文/英文最长文案不溢出（侧栏标签、模型名、按钮）
- [ ] 所有视觉值来自 `tokens.css`（`test_design_tokens.py` 守护）
- [ ] Chat 的三种状态（空 / 有消息 / 流式中）都像同一个 App
- [ ] `prefers-reduced-motion` 下无位移动画
