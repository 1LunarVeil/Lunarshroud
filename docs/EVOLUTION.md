## 一、项目定位与产品边界（不重议）

`LunarShroud` 是 llama.cpp `llama-server` 的 Windows 图形化启动器（Tauri 外壳 +
FastAPI/Python 后端 + 零构建原生 ESM 前端）。刻意边界：

- **不打包、不自动下载 llama-server**：路径默认留空，由用户显式选择（安全不变量，
  见 AGENTS §2.1）；README 指引获取方式。
- **双通道发布是硬要求**：可 clone 源码自编译，也可用 NSIS 安装包/便携运行时。
- **参数界面跟随本机构建的能力**：schema 是静态快照，`--help` 探测才是权威；
  界面渲染、命令行丢弃、默认值省略全部由探测结果驱动（三态：支持/不支持/未知）。
- 候选版本号 `0.9.0-beta.1`；未签名、未做完整硬件 soak 之前不称 stable。

## 二、演进阶段

### 阶段 0：诞生（≤ 2026-08-16，0.9.0-beta.1 候选）
基础启动器：实例生命周期、预设、历史、日志、监控、设置。发布纪律从第一天就存在：
配对部署（launcher + backend 两个 EXE 成对哈希校验）、桌面快捷方式由
`tools/Publish-PortableRuntime.ps1` 统一维护。

### 阶段 1：参数正确性与自适应（P0–P5 演进，2026-08-17 ~ 09 中旬）
核心转折：**把三份硬编码契约收敛为一份探测真相**（规划与实测记录见
`docs/archive/plans/` 内的演进规划原件，已完成切片索引见其"执行进度"）。

- P0 止血：推测解码配置正确性（`draft-ngram` 非法值直接启动失败等）。
- P1 治本：GGUF 能力探测（`core/gguf_probe.py`）、llama-server 能力探测
  （`core/server_probe.py`）、能力聚合层（`core/capabilities.py`）——"参数界面
  跟随本机构建"从口号变成机制。
- P2 前端信息架构重构：二级左栏、设置浮层+分类导航、契约与结构清理。
- P3 模型库与调参体验：模型列表能力徽章、单模型能力卡片、一键推荐、显存预估。
- P4/P5：Chat 页（WebUI 嵌入 + 非回环降级）、模型选择器（Ctrl+L）、完整 i18n、
  发布与工程化收口（coverage 门限、镜像门禁、CI）。

### 阶段 2：安全审计与七轮整改（2026-09 中旬 ~ 10-14）
首轮全面审计（只读轮）产出 `全面审计文档.md` §1–§11：3×P1（令牌泄露、extra_args
越权、可写目录自动执行）、4×P2、若干 P3。其后七轮整改逐步闭合，并留下两类沉淀：

1. **不变量清单**（§2 的 S1–S7 → AGENTS §2.1–§2.9）：空默认 exe、ready 端点
   反向认身份、extra_args 黑名单、子进程环境剥离 `LUNARSHROUD_*`、内容级脱敏、
   GGUF 解析预算、WS 信任随端口派生、PowerShell 5.1 两条硬规则、重启链按根串行。
2. **验证纪律**（AGENTS §6）：红-绿回归、跑命令留输出、UI 改动真开浏览器。

轮次摘要（细节在总卷 §12.x）：第二轮 F1–F8/F12/F22；第三轮修补 F3 缺口 + 空默认；
第四轮重建部署 + 实测 37 断言（含首个 PowerShell 5.1 部署事故）；第五轮首启 UI
走查（R9 端口写死信任表，实时推送"半死不活"）；第六轮 F9 重启并发（复现、修复、
并证伪自己第一版修复）；第七轮 F10/F11/F13/F14/F15/F19/F20/F21/F23/F24 + e2e 端口
动态化 + F10b 单飞 + 抖动测试修复（§12.16/§12.17）。

### 阶段 3：独立盲审与最新能力对齐（2026-10-14）
独立审计（未读既往结论、独立实验取证）确认工程质量高于同类桌面启动器，并发现：

- **H1（高）**：能力探测对"包装脚本/挂起型"目标无真正超时（实测挂起 585s）、
  孙进程孤儿、单飞跟随者线程永生 → 线程池饿死 → 实例管理 API 全面瘫痪。
- **M1（中）**：重启/历史重启不写启动历史（页面承诺 vs 实现不一致）。
- **L1/L2（低）**：实例日志无界且永不清理；带 BOM 的 config.json 被当损坏重置。
- I1/I2：过期构建物、`.bak`/孤儿 `.pyc` 卫生问题。

全部修复并红-绿固化（探测改进程树回收 + 跟随者总截止；三条启动路径共用历史回调；
实例日志轮转 + 随实例/剪枝清理；配置读 `utf-8-sig`；卫生清理）。

同时按"不落后于 llama.cpp"原则加装 **AI 工具与 MCP 参数组**（构建驱动自动置灰）：
`--agent` / `--tools` / `--tools-runtime` / `--ui-mcp-proxy` / `--mcp-servers-config`
/ `--rerank`。对齐目标为**用户实际运行的官方构建**（0.6.0-dev / build 11630）；
首批快照来自 prism-ml fork（b10709），两方同名能力已互证。随官方版第二批新增：
MoE 族（`--cpu-moe` / `--n-cpu-moe` / `--n-cpu-ffn` / `--moe-cache-mib`）、
草稿微批与采样（`--spec-draft-n-ubatch` / `--spec-draft-sampling`）、
视频输入（`--video-fps` / `--video-ffmpeg-dir` / `--video-timestamp-interval`）、
`--lazy-mode`。RAG 能力说明：llama.cpp 无独立 RAG 开关，落地路径 = 内置 agent 工具
（read_file/grep_search/…）+ MCP servers + `/v1/embeddings` + `/rerank` 的组合，
本启动器已把这条链路的参数全部暴露（详见总卷 §12.18）。

### 阶段 4：二轮复核收口与 v0.7.0 对齐（2026-10-16 ~ 10-17，本轮）
二轮独立复核（自带隔离实验，并补做了首轮未做的真实浏览器点击走查）确认
H1/M1/L1/L2 为实质修复，三项残留当轮全部收口：N1 探测跟随者并发闸门（每目标
上限 + 快速失败，不占满工作线程池）、N2 历史重启改为自动分配端口、N3 补
`--mcp-servers-json`。真实模型冒烟（官方 build 11630）证明 `--agent` 确实进入
argv、`/tools` 由 403 翻 200、真实对话 1.3s 返回。

随后本机 llama.cpp 升级到 **0.7.0-dev (build 11698)**，本轮工作围绕它展开：

- **选项面没变，行为面变了**：与 11630 逐行 diff 后是 258 个不同选项、零增减，
  唯一文案变化在 `--cache-ram`（"0 用于决策模型"）。真正的变化是上游默认端口
  8080 → 9931、聊天会话 API 改为分部分结构、WebUI 新增模型管理器与路由模式。
  Chat 页是 iframe 内嵌上游 WebUI、自己不解析聊天 JSON，所以 API 重构落不到
  本仓库代码上；内嵌所需的框架头（`COEP: require-corp` / `COOP: same-origin`）
  经 git 追溯是 2026-06-13 引入，早于已验证过的 11630。
- **补齐能力面缺口**（全部构建驱动，旧构建自动置灰 + 丢弃留痕）：检索侧
  `--pooling` / `--embd-normalize` / `--cache-prompt`；路由 `--models-dir` /
  `--models-max`；思考控制 `--reasoning` / `--reasoning-format` /
  `--chat-template-kwargs`；分布式 `--rpc`。
- **能力层两处修正**：参数位上的取值声明（`{a,b,c}` / `[a|b|c]`）现在能解析，
  这些下拉框从此跟随本机构建而不是静态快照；select 校验改为"以本机构建声明的
  取值为准"，修掉"界面能选、启动却 400"这条自相矛盾。
- **RAG 产品化选了用途配方，而不是内置预设**：预设是被刻意移除的（调优数字必然
  随版本漂移，见 CHANGELOG 的 Removed 与 `preset_store` 模块文档）。配方只写
  意图（这是嵌入服务 / 那是只读工具服务），键过 schema、能力过探测，双重过滤；
  `docs/RAG.md` 记录构件清单与 8GB 卡双实例实测布局（86MB Q4_K_M 嵌入模型出
  768 维向量，与 4B Q4_K_M 对话模型 `-c 8192` + 只读工具同时在线）。
- **冒烟中撞到的崩溃是上游缺陷，不是我们的**：嵌入模型 + 单槽位 + 未开
  `--embeddings` → `GGML_ASSERT(n_outputs_max <= cparams.n_outputs_max)` abort。
  逐 flag 二分定位（`-np 1` 单独即可触发；`--kv-unified` / `-fa` /
  `--models-dir` 全部无关），两条规避都经启动器端到端实测通过，并把这条断言接进
  崩溃翻译层 —— 此前它既不匹配 `assertion` 也不匹配 `ggml_abort`，日志里写着死因、
  界面上却一个字都不显示。

## 三、工程规则沉淀（现役条目）

- **动手前**：读 AGENTS.md；任何"文档写了、代码没做"的断言都视为未验证。
- **改动后**：`pytest backend/tests` + `ruff check backend tools` +
  `tools/check_release_mirror.py`；前端 `node --test`；Rust `cargo fmt/clippy/test`。
- **回归**：红-绿——先让新测试在错误版本上变红，再修到绿；只"写完就绿"的测试可疑。
- **发布**：镜像 `--apply` 后必须复查 CLEAN；配对重建 + 成对部署；产物按构建者
  身份字节扫描（ASCII + UTF-16LE）。
- **依赖**：`backend/requirements.lock` / `requirements-dev.lock` 哈希锁定（纯 ASCII，
  再生成方法见锁头注释）。
